# Changelog

Applies when the project has a `CHANGELOG.md`.

After completing a feature or fix:

1. Decide if the change is user-facing (new behavior, changed behavior, removed behavior, user-visible fix).
2. If yes, add a concise entry under `## [Unreleased]`, matching the file's existing sections and wording style. Create `## [Unreleased]` at the top if missing.
3. Skip internal refactors, tests, chores, and CI changes.
4. State the changelog decision in the Final report.
